# Хочу — исправленная рамка, версия для Git

## Что исправлено

Белая полоска сверху была не частью записи, а подложкой видеоконтейнера. Внутренняя область макета и ролик имели немного разные пропорции; `object-fit: contain` оставлял свободное место. На светлой подложке и при наклоне телефона оно выглядело как белый зазор.

Теперь внутренняя область экрана рассчитывается по реальным размерам активного видео/изображения и равномерно размещается внутри корпуса. Оставшееся место относится к тёмной рамке, а не к белой подложке. Изображение по-прежнему вписывается целиком, без дополнительной обрезки, растягивания или приближений. Скругления сохранены. Исправление работает в макете, при его наклоне и в исходном увеличенном просмотре.

Внешний размер телефона, расположение заголовков/навигации/иллюстраций и тексты не изменены. Лоадер с круговым заполнением из центра сохранён. Элементы плеера остаются скрытыми. Все шесть видео скопированы из последней версии побайтно, без повторного пережатия.

## Для Git и публикации

Распакуйте архив и загрузите **содержимое этой папки** в корень репозитория, из которого публикуется сайт. Не загружайте вместо него старый автономный HTML на 31,8 МБ и не используйте ZIP как саму страницу сайта.

Стартовая страница — `index.html`. Ей нужны соседние файлы и папки:

```text
index.html
styles.css
frame-fit.css
scripts/
assets/
```

HTML, CSS, JavaScript и изображения разнесены по отдельным файлам. Повторяющиеся встроенные изображения сохранены один раз, без изменения их байтов. Ни видео, ни картинки дополнительно не сжимались с потерями. У проекта нет npm-зависимостей, сторонних шрифтов, CDN или обязательного сервера приложения.

Каждый файл проверен относительно заданного лимита: **меньше 25 000 000 байт**. Самый большой файл — `assets/search-rounded-light.mp4`, 5 884 117 байт (5,88 МБ). Git LFS для этих файлов не требуется по указанному размерному ограничению.

Проверить размеры после следующих обновлений:

```sh
python tools/check_file_sizes.py
```

Локальный просмотр, например через установленный Python:

```sh
python -m http.server 8000
```

Затем откройте `http://localhost:8000` на этом же компьютере. Команда не публикует сайт в интернете. Для проверки с телефона используйте адрес вашего размещённого сайта в браузере.

`.gitignore` исключает архивы, локальные логи и служебные каталоги, но не исключает рабочие видео. `.nojekyll` оставлен для обычной статической публикации. В папке нет гигантского автономного HTML, исходных скринкастов или дубликата полного сайта внутри ZIP.

## Что где находится

- `styles.css` — исходные стили в том же порядке каскада.
- `scripts/01-app-loader-v31-js.js` — прежний лоадер, без изменения логики или вида.
- `scripts/02-config.js` — исходные настройки; укажите реальную ссылку в `appStoreUrl`, когда она доступна. Пустая ссылка сохранена из предыдущего файла.
- Остальные пронумерованные скрипты — прежние сценарии сайта, в исходном порядке выполнения.
- `frame-fit.css` и `scripts/frame-fit.js` — только исправление прилегания экрана к рамке.
- `assets/*.mp4` — шесть действующих видео из последней версии. Указатели кликов и свайпов не изменены.
- `assets/images/` — ранее встроенные изображения, теперь отдельными файлами.
- `BUILD_REPORT.json` — сравнение текста/SVG, контрольные суммы и размеры медиа.
- `QA_REPORT.json` — результаты проверки страницы.
- `FILE_SIZES.json` — перечень размеров при подготовке пакета.

## Проверка

В Chromium проверены все восемь разделов на шести размерах окна: 320×568, 390×844, 416×780, 768×1024, 844×390, 1440×1000. Внешние размеры и позиции ключевых элементов сопоставлены с предыдущей версией. Проверены пропорции растровой области, воспроизведение каждого видео, увеличенный просмотр, переключение в нём, скрытые элементы плеера, наклон макета и системное уменьшение движения. Отсутствующие ресурсы и ошибки JavaScript в этих проверках не обнаружены.

Проверки выполнялись в headless Chromium. Пакет с отдельными ресурсами загружался через локальный обработчик запросов Playwright, включая ответы на диапазоны байтов для видео. На физическом iPhone, в Safari и на реальном хостинге эта версия не тестировалась.
